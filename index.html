Saludo. Este trabajo nace del curso de Introducción a la Programación (IP) de Uniandes: más de 1.000 estudiantes por semestre y un calificador automático, Senecode, que dice qué falló pero casi nunca por qué. Preguntamos si un modelo pequeño, adaptado con datos del curso, puede dar retroalimentación de calidad comparable a un LLM comercial respetando las restricciones del curso.

01 · The course

Introduction to Programming (IP)

1,000+

students per semester, required across several academic schools

25

students per section, many sections taught in parallel

4

levels, each restricting the constructs students may use

Level 1

Variables, int / float / str, functions, composition

Level 2

Conditionals, bool, Boolean expressions

Level 3

Loops, lists, dictionaries, traversal patterns

Level 4

Matrices; pandas, Matplotlib, NumPy

Practice driven: two lectures and one lab per week, graded Python exercises at every level. At this scale, sustained instructor feedback is hard.

IP es obligatorio en varias facultades. Para mantener consistencia entre secciones el curso se apoya en práctica: ejercicios calificados en cada nivel. Cada nivel restringe qué construcciones puede usar el estudiante (por ejemplo, nada de ciclos antes del nivel 3). Esa restricción será clave después: la retroalimentación no puede sugerir cosas que aún no se han visto.

02 · The grader

Senecode: fast and trusted, but terse

6 years

in use in the course

700,000+

submissions graded with unit tests

Unlimited

resubmissions, no penalty, near immediate result

Submitted function

def height_in_m(feet, inches):

    total = inches + feet * 12

    meters = total * 2.54 / 100

    return meters

What Senecode reports

FAILED  height_in_m(6, 0)

expected: 1.83    got: 1.8288

It tells students what failed, barely why. Students have asked for more specific guidance on the causes of failures, and any new mechanism must keep Senecode's reliability.

Senecode califica cada función con pruebas unitarias y compara salidas. Si pasa todo: nota máxima. Si falla, muestra el resultado esperado y ya. Ejemplo real del conjunto: el estudiante no redondea a dos decimales; Senecode dice "esperaba 1.83, obtuve 1.8288". Es correcto pero no explica la causa. La confianza de estudiantes y profesores en Senecode (6 años, 700 mil envíos) es un activo que no podemos poner en riesgo con retroalimentación equivocada.

03 · The gap

Students need the why. At what cost?

Commercial LLMs

GPT-4o Mini · Claude 4.5 Haiku

  • + Detailed natural-language explanations
  • − Recurring cost: 1,000+ students × unlimited attempts
  • − Not built for course rules: may suggest constructs not yet taught, or the full solution

Off-the-shelf SLMs

1–1.5B parameters, local

  • + Cheap; runs on a 16 GB GPU already on campus
  • − Prone to inaccurate or hallucinated explanations
  • − Novices cannot tell good feedback from bad

Five design constraints

Non-disclosive

Course-level

Reliable

Cost-efficient

Low compute

Can a cost-efficient, adapted SLM approach commercial-LLM quality while satisfying introductory-programming constraints?

Los LLM comerciales explican bien, pero cada intento cuesta y no conocen las reglas del curso: pueden sugerir un ciclo en nivel 1 o entregar la solución. Los SLM son baratos y locales pero alucinan, y un novato no puede detectarlo. De ahí las cinco restricciones de diseño: no revelar la solución, respetar el nivel, ser confiable, costo sostenible y poco cómputo. Pregunta de investigación en azul.

05 · Approach

An adapted SLM, minimal diagnostic context

Exercise statement

with the level's construct restrictions

Reference solution

to spot deviations, never to be shown

Submitted code

a failing attempt

Extended unit tests

inputs, expected vs actual, and the purpose of each test

Qwen2.5-Coder-1.5B

QLoRA adapter trained on human-written feedback · 4-bit · fits a 16 GB GPU

Feedback to the student

  • 1–2 bullets, addressed to the student
  • Never the solution, never code
  • Only constructs of the current level
  • In Spanish, the course language

Only what is needed to diagnose the failure: long, irrelevant context degrades small models (Liu et al., 2024).

El prompt tiene cuatro elementos: enunciado con restricciones del nivel, solución de referencia, código enviado y las pruebas unitarias extendidas. Todo pasa por Qwen2.5-Coder-1.5B con un adaptador QLoRA. La salida es una retroalimentación de uno o dos puntos, dirigida al estudiante, sin código ni solución, dentro de lo visto en el curso. Deliberadamente damos poco contexto: un modelo pequeño se distrae con información irrelevante.

06 · Extended unit tests

A failed test now names its requirement

Plain test (Senecode today)

>>> result = height_in_m(6, 0)

>>> round(result, 2) == result

True    # expected

False   # got

 

 

The model sees a mismatch and must guess which requirement it violates.

Extended test (this work)

>>> result = height_in_m(6, 0)

>>> round(result, 2) == result

True    # expected

False   # got

Test 2 · verifies rounding to 2 decimals

builds on Test 1 (return type is float)

The rounding requirement is unmet: enough evidence for a targeted, non-revealing hint.

Descriptions are hand-written per test under the non-disclosive, course-level and reliability constraints: evidence about the failure, not the answer.

Nuestra primera contribución técnica. A cada prueba unitaria le agregamos una descripción en lenguaje natural de su propósito y de qué pruebas depende. Con la prueba plana, el modelo ve "True vs False" y tiene que adivinar; con la extendida sabe que lo que falla es el redondeo a dos decimales. Las descripciones las escribe el equipo docente cuidando no revelar la solución ni usar conceptos fuera del nivel.

07 · Adapting the model

Qwen2.5-Coder-1.5B, adapted with QLoRA

Why this base: code-specialised, supports program reasoning, fits the 16 GB GPU already on campus, and the newest Qwen coder at this size (Qwen3-Coder starts at 30B).

Training data

  • 270 synthetic failing submissions over 50 course exercises
  • Each with reference solution, extended unit tests and feedback written and peer-checked by a 5-person instructional team
  • Real student code not reused (secondary-use limits); only its recurring error patterns, mined from frequently failed tests
  • 70 / 30 train / validation split

QLoRA configuration

  • 4-bit base, 16-bit LoRA adapters
  • r = 16, α = 32, dropout 0.05
  • lr 2e-4, batch 2 × grad. accum. 8
  • max length 2048, 3 epochs, 4 warmup steps
  • loss only on the feedback tokens

Goal: align format and behaviour with the course constraints, not teach the model new programming knowledge.

Elegimos un modelo que ya sabe de código y lo adaptamos, en vez de entrenar desde cero. Datos: 270 envíos sintéticos incorrectos sobre 50 ejercicios del curso; no pudimos reusar código real de estudiantes, así que reprodujimos los patrones de error más frecuentes. Cada ejemplo lleva retroalimentación escrita por el equipo docente y revisada por pares. QLoRA: base en 4 bits, adaptadores LoRA, configuración estándar. Importante: los cinco que escribieron esta retroalimentación no participaron después como evaluadores.

11 · Conclusions

Contributions

1

Domain adaptation works for this task

Qwen2.5-Coder-1.5B went from 5.34 to 9.01 / 10, statistically tied with Claude Haiku (9.05); GPT-4o Mini remains ahead at 9.58.

2

Reliability improved the most

Hallucination-free feedback rose from 21.6% to 91.0%, above Claude Haiku's 77.0%. Consistent with adaptation aligning format and constraints, not adding programming knowledge.

3

Extended unit tests + human-written feedback

Linking each failed test to the requirement it checks gives a 1.5B model enough evidence for course-aware, non-disclosive feedback at negligible cost.

Backup · Limitations

Limitations

Scope

One SLM, one course, a limited exercise set. Held-out submissions come from exercises seen during adaptation, so overfitting to the pool is not excluded.

Synthetic submissions

Built from recurring error patterns in Senecode's history, all incorrect by design; they do not reproduce the full distribution of authentic student code.

Evaluators

Insiders highly familiar with the course; one reviewer per sample, so inter-rater reliability was not measured.

Baselines and inputs

No comparison with knowledge distillation or self-supervised repair strategies; prompts use test execution only, no static program analysis.

Diapositiva oculta, para preguntas. Cuatro limitaciones: alcance, envíos sintéticos, evaluadores internos sin medida de acuerdo entre revisores, y ausencia de comparación con destilación o análisis estático.

Backup · Evaluation criteria

Seven criteria for feedback

Supportive

Encourages the learner; constructive, non-discouraging tone (Shute; Brookhart)

Selective

Focuses only on relevant issues; no unnecessary or nonexistent fixes (Koutcheme et al.)

Accurate

Correctly identifies the student's actual mistakes (Koutcheme et al.)

Non-revealing

Actionable guidance without disclosing the solution (Scarlatos et al.; Shute)

Concise

Only the necessary information, no superfluous detail (Shute; Narciss)

Novice-appropriate

Language accessible to novice programmers (Denny et al.)

Hallucination-free (yes / no)

No fabricated, unsupported or wrong claims about the code or its behaviour (Maynez et al.)

Backup · Design constraints

Five design constraints

Non-disclosive

Help students find and fix errors without giving the solution or code; general LLMs may hand over explicit hints or full implementations.

Course-level

Only constructs the student is expected to know at that level; no advanced features or explanations beyond the prerequisites.

Reliability

Correct and clear; hallucinated explanations mislead novices, and long irrelevant context makes them more likely.

Cost

Many students, unlimited resubmissions: paying a commercial LLM per failed attempt is hard to sustain.

Computational resources

Many parallel submissions on shared academic infrastructure: a small model that fits a 16 GB GPU is preferable to a large local LLM.
